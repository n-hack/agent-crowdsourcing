# 05 応募文の型

## 共通の決まり
- 依頼文に「応募時に答えてほしい項目」があれば、その番号と順のとおりに全部答える（こちらの型より先）
- 1行目は宛名（下の「宛名の決め方」）→ 名乗り → 「何のご依頼と読んだか」を1文 → 応募の理由
- 進め方を番号で3〜5段。最初に「作業の前に丸ごと控えを取る」「本番を止めない」など、相手が怖がっている所を消す一文を入れる
- 金額と納期は数字で。CW の入力欄は税抜。本文の額には必ず「（税込）」か「（税抜）」を付ける（型は「（税込）」＝.json の金額×1.1。確かめの道具はこの書き方で照らす・付けないと照らされない）
- 納期は最短の具体的な日付で書く（「数日以内」「件数が決まってから」とぼかさない・相手の締切いっぱいの日付も出さない）。型も「{納品の日付}までに納品します」の日付の形（「◯日以内」の形は使わない）。既定は「契約の当日〜2日後」。大きい仕事は「最初の段（構成案・最初の◯件）を契約の翌日に」と書き、全体の日付も前に寄せる。納品日が遅いと選ばれない（オーナーの判断・2026-11-06）。経歴がなくても同じ
- 送る前に、その時点の提案数（ランサーズ）・応募した人（CW）を見て記録に残す。人数だけでは外さない。cwapply.cjs は20人を超えると 🟡 を1行出すだけで止めない（2026-11-07 の数：人数が多い帯でも返事率は下がっていなかった・docs/08「応募した時点の人数ごとの返事率」。11/04 の「20を超えたら決め直す」と docs/10 の「応募30人以上を外す線」は、この数より前の決めなので採らない）。巡回（cw-junkai.py）にも人数で外す処理は無い。経歴がなくても同じ
- 見本サイトを出す前に `python3 tools/mihon-kensa.py <公開フォルダ>` を通す。空欄「〔…〕」の残りと、頁が貼っている画像・動画が手元に在るかを全頁で数え、1件でも🔴なら出さない（11/04 実例：フォルダごと出す形で、どこにも貼っていない作りかけの頁が公開されていた）。経歴なしでも再現：する
- ランサーズの提案の金額欄も税抜。依頼主が「税込1万円」と書いていたら 9,091 と入れる（10,000 と入れると総額 11,000 になる・送る前の確認画面の小計と消費税を見る）
- 同じ依頼主の別の募集に出すと、二重応募の確かめが「同じ依頼主・似た題名」で止めることがある。中身（チャンネル・対象・納品物）が違うのを確かめてから出し、提案文に「別の募集にも提案しています」と1行書く（経歴がなくても同じ）
- 稼働を書く：「土日・夜も対応・メッセージは届いたらすぐ返します」（エージェントの強み＝24時間動ける）
- 実績が無いなら無いと書く。代わりに、自分で作った見本の URL と「最初の小さな段（最初の◯件・1ページ分）を仕上げてお見せし、形を確かめていただいてから残りを進める」を書く。額は下げない（docs/04 の「5 値段」の道具の額だけ・2026-11-06 の決め）。🔴「無料で試作」「仮払い前にテスト1本」は書かない（CW 規約23条(31)が仮払い前の作業を禁止・ランサーズのガイドも提案にサンプルを付けない・開始前に作業しないよう求めている）
- 結び「よろしくお願いいたします」・最後の行に署名
- 送る前に `node tools/shitagaki-kakunin.cjs <下書き>` を通す（下の「下書きの穴を埋める」の手順6。manner-mon（oubo）と jisseki-mon もこの中で呼ぶ）

## 宛名の決め方（1行目）
表示名は CW の募集の頁の依頼主の名前（巡回の tsv の「依頼主」の列と同じ）を、そのまま1字も変えずに写す。分けたり、略したり、「株式会社」だけ残したりしない。
| 表示名 | 宛名 | 崩した例（書かない） |
|---|---|---|
| 個人の名前・ニックネーム（kom_2020・山田太郎） | `kom_2020様`・`山田太郎様` | `kom_2020 ご担当者様` |
| 会社の形の付いた名前（株式会社高電社・合同会社〇〇） | `株式会社高電社 ご担当者様` | `株式会社 様の担当者様`（名前が抜けた）・`株式会社 様`・`株式会社高電社様`・`株式会社高電社 御中 ご担当者様`（御中と様を重ねた） |
| 会社名・屋号だけ（高電社・ECサイト運営コンサル） | `高電社様` のまま。本文やクライアント情報で会社と分かれば `高電社 ご担当者様` でもよい | `高電社様の担当者様`・`高電社様 ご担当者様` |
| 空・分からない（巡回の tsv で「-」） | `ご担当者様` | `様`・`担当者様` |
- 段3の道具（oubo-shitagaki.cjs）が表示名から上の形で1行目を作る（会社の形の語＝株式会社・有限会社・合同会社・社団法人・財団法人・(株) があれば「ご担当者様」）。エージェントは1行目を書き直さなくてよい。直すのは、表示名が「-」で本文に会社名が書いてある時だけ（その会社名をそのまま写して「ご担当者様」）
- 確かめ（shitagaki-kakunin.cjs）が、「様の担当者」「様 ご担当者様」「御中 様」「様様」・名前の無い「株式会社 様」・会社の形に直接の「様」・巡回の tsv の表示名と違う宛名を 🔴 で止める
- 2026-11-06 の試し4回目の実例：素のエージェントが表示名「高電社」の1行目を一度「株式会社 様の担当者様」と崩し、自分で戻した。経歴なしでも再現：する（宛名は表示名だけで決まる）

## 下書きの穴を埋める（mawasu.sh の段3の後・エージェントがやる）
「下書きまで」「応募の手前まで」と頼まれたときも、この手順1〜6までがエージェントの仕事（docs/00 の「止まる所」）。段3で道具が作るのは宛名・名乗り・署名だけの型で、ここで止めると送れる下書きは 0件のまま。止まるのは、手順6の3つ（穴の残り 0・manner-mon が何も出さない・jisseki-mon が何も出さない）を通した後。送るのはオーナーの OK と `--go` の後。
段3の下書き（`<置き場>/oubo-bun/cw-<ID>.txt`）は、道具が宛名・名乗り・署名だけを埋めた形。中身の穴は templates/oubo-kihon.txt の6つが残る（作ったときに oubo-shitagaki.cjs が「🟡 埋める穴 6つ：{何をどうしたいご依頼か1文} {最初に確かめること} {作業の中身} {金額} {納品の日付} {見本のURL}」と出す）。
1. 募集の本文を開く：`https://crowdworks.jp/public/jobs/<ID>`（ログインなしで読める・門の cw-tantei.py が読むのと同じ頁）。「仕事の詳細」から「クライアント情報」の手前まで全部読む
2. 先に下の「応募できない募集の見分け方」に当てる。当たったら埋めずに見送りの記録を書いて次の下書きへ（1件止まっても、残りの下書きを読み続ける）
3. 依頼文に「応募時に答えてほしい項目」があれば、型より先にその項目を番号順で本文に足す（共通の決まり）
4. 穴を埋める

| 穴 | 何で埋めるか | 書かない物 |
|---|---|---|
| {何をどうしたいご依頼か1文} | 本文の依頼内容を自分の言葉で1文（何の・何を・どうしたいか） | 本文の丸写し |
| {最初に確かめること} | 作業の前にもらう物・見る物（今の状態・データの一部・権限など） | 本文に無い相手の事情 |
| {作業の中身} | 使う道具と作る物（「GAS で取り込みと集計を作り…」）。道具の指定が本文にあればそれ | 使ったことのない道具を「経験あり」と書く（型F） |
| {金額} | 手順5の道具（cw-souba.py）が出した税抜の額×1.1（型の「（税込）」に合わせる・1円未満は四捨五入＝確かめの道具と同じ丸め） | 「相談」のまま・道具を打たずに決めた額 |
| {納品の日付} | .json の納期と同じ日を「11月9日」の形で（既定は契約の当日〜2日後・共通の決まりの納期） | 相手の締切いっぱい・「◯日以内」 |
| {見本のURL} | この募集に合わせて作った見本の公開の URL（下の「応募の前に見本を作って添える」）。ランサーズは提案文に外の URL を書けない（docs/02）ので「ポートフォリオの『◯◯』をご覧ください」に置き換える | 合う見本が無いとき：見出しの行ごと2行を消す（穴を残さない）。見本の無い物をあるように書かない |

5. 同じ名前の `.json` に `金額`（税抜の数字）と `納期`（`YYYY-M-D`・既定は今日から2日後まで。長くするなら `納期の理由` を1行）を書く。.json はランサーズの下書きでも `YYYY-M-D`（確かめの道具がこの形で読む）。ランサーズで送るときだけ teian.cjs に `YYYY/MM/DD`（例 2026-11-9 → 2026/11/09）に直して渡す（CW の cwapply.cjs は `YYYY-M-D` のまま）。`金額の根拠` も（帯のある募集も無い募集も）。ランサーズは `計画の題名`（20字以内）と `計画` も。
   - 型の「進め方」の固定の2行（「2．作業の前に今の状態を控えておきますので…」「4．終わったら動作を確かめ…」）は、その募集の言葉で書き直す（そのまま残すと手順6で止まる）。例：新しく作る頁なら「2．新しく作る頁は公開前の仮の場所で組み、今の LP の表示には手を入れずに進めます」。事実と違う行を型のまま残さない
   - 金額：本文か頁の上の「固定報酬制」に予算の帯があれば、税込（.json の金額×1.1）がその帯の中に入る額にする（帯は税込で出る・2026-11-06 に確かめた：帯の上限 110円の募集の本文が「契約金額(税抜) 100円」）。帯があるときも額は自分で決めず `python3 tools/cw-souba.py --id <ID> --obi <帯の下限>-<帯の上限>`（帯は税込の円・額は帯の上限×0.6 で決まり相場は引かない）を打ち、「帯のある募集の額」をそのまま .json の金額にし、最後の1行（「金額の根拠（帯のある募集…）」）を `金額の根拠` に写す（試し8回目：道具を打たずに 50,000円と書いた体がいた・正しくは 45,000円）。帯が無い（「ワーカーと相談する」）ときは `--obi` を付けずに打ち（付けると道具が止まる）、出た1行を `金額の根拠` に写す。どちらも空なら手順6の確かめが止める。本文に「◯円（税込）」と書いたら .json の金額×1.1、「◯円（税抜）」なら .json の金額と同じ数にする
6. 確かめる：`node tools/shitagaki-kakunin.cjs <置き場>/oubo-bun/cw-<ID>.txt`（引数なしで置き場の下書き全部）。✅ が出てから、送る段＝オーナーの OK と `--go` へ。🔴 の行を直して打ち直す（rc=2 のうちは送らない）
   | 見る物 | 止まる時 |
   |---|---|
   | 穴の残り | `{…}` が1つでも残る |
   | 型の行の残り | 型の「進め方」の固定の行がそのまま（手順5） |
   | 宛名 | 上の「宛名の決め方」の崩れ・巡回の tsv の表示名と違う |
   | 金額・納期 | .json の金額が空・納期が YYYY-M-D でない・今日より前 |
   | 納期の日数 | .json の納期が本文の締切・日数（「納品まで5日以内」「11月20日まで」・応募や募集の締切は数えない）より後／既定（今日から2日後）より後で .json に `納期の理由` が無い／下書きの「◯日以内」（今日からの日数と1日より多くずれる）・「◯月◯日まで」が .json と合わない（公開頁が読めなければ「納期を照らせず」で止まる） |
   | 予算の帯 | 税込（金額×1.1）が帯の外（帯は巡回の tsv、無ければ公開頁から読む・どちらも読めなければ「帯を照らせず」で止まる） |
   | 帯の無い募集 | .json に `金額の根拠`（tools/cw-souba.py の最後の1行）が無い |
   | 帯のある募集 | `金額の根拠` に cw-souba.py --obi の「帯のある募集の額」が無い・その額と .json の金額が違う |
   | 本文の金額 | 本文の「◯円（税込）」「◯円（税抜）」が .json と合わない |
   | マナー・AI 臭さの門 | manner-mon.cjs（oubo）が 🔴 を出す（🟡 は出すだけ） |
   | 成果の言い方の門 | jisseki-mon.cjs が1行でも出す |
   実測（2026-11-06・試しの置き場）：試し4回目の下書き7件では通った 1・止めた 6（埋めた2件のうち 13538763 は型の行2行が残ってこの確かめで止まり、13585056 は通った）。1つずつ壊した対照 14件は14件とも狙った理由で rc=2、直した物・帯の中・帯の無い募集の5件は rc=0。段4（`--go`）もこの確かめを通った下書きだけを「送れる下書き」に数える（tools/mawasu.sh）。経歴なしでも再現：する
7. 穴が残った物は送らない。道具の側も、`{…}` が1つでも残る下書き・.json の金額・納期が空の下書き・手順6の確かめで 🔴 の下書きは段4の「送れる下書き」に数えない（tools/mawasu.sh の段4の実装）。`--go` でも送られないが、出したことにもならない（段6で出し漏れに数えられる・docs/12）

実測（2026-11-06・試しの置き場）：素のエージェントが作った下書き12件は、穴を埋めずに止まり、AI 臭さの検査で12件とも 🔴。🔴 の中身は12件とも「型の穴埋めが残っている」の1種だけで、ほかの 🔴 は0件だった。架空の募集（CSV の集計を GAS で自動にする）で5つの穴を埋めた下書き1件は、manner-mon・jisseki-mon とも何も出さずに通った（n=1。本物の募集で埋めた物を通したのは未確認）。経歴なしでも再現：する（穴は募集の本文と自分の作り方だけで埋まり、経歴の行は無い）

## 応募の前に見本を作って添える（11/04）
- 作れる物は「できます」と書き、その根拠をその場で作る：案件と同じ形の小さな物（動く頁・実行の記録・出た表）を作り、公開して URL を型の {見本のURL} に入れる（公開はオーナーの OK の後・上の型F）
