# 05 応募文の型

## 共通の決まり
- 依頼文に「応募時に答えてほしい項目」があれば、その番号と順のとおりに全部答える（こちらの型より先）
- 1行目は宛名（依頼主の表示名＋様／分からなければ「ご担当者様」）→ 名乗り → 「何のご依頼と読んだか」を1文 → 応募の理由
- 進め方を番号で3〜5段。最初に「作業の前に丸ごと控えを取る」「本番を止めない」など、相手が怖がっている所を消す一文を入れる
- 金額と納期は数字で。CW の入力欄は税抜、本文は税込で書くなら両方を合わせる
- 納期は最短の具体的な日付で書く（「数日以内」「件数が決まってから」とぼかさない・相手の締切いっぱいの日付も出さない）。既定は「契約の当日〜2日後」。大きい仕事は「最初の段（構成案・最初の◯件）を契約の翌日に」と書き、全体の日付も前に寄せる。納品日が遅いと選ばれない（オーナーの判断・2026-11-06）。経歴がなくても同じ
- 送る前に、その時点の提案数（ランサーズ）・応募した人（CW）を見る。20を超えていたら、出すかを決め直す（評価0のうちは、混んだ場で選ばれた実例がまだ無い・11/04 時点で採用0）。道具に組むなら「止める」ではなく「1行出す」から始め、採用のデータが出てから線を引く（経歴がなくても同じ）
- 見本サイトを出す前に `python3 tools/mihon-kensa.py <公開フォルダ>` を通す。空欄「〔…〕」の残りと、頁が貼っている画像・動画が手元に在るかを全頁で数え、1件でも🔴なら出さない（11/04 実例：フォルダごと出す形で、どこにも貼っていない作りかけの頁が公開されていた）。経歴なしでも再現：する
- ランサーズの提案の金額欄も税抜。依頼主が「税込1万円」と書いていたら 9,091 と入れる（10,000 と入れると総額 11,000 になる・送る前の確認画面の小計と消費税を見る）
- 同じ依頼主の別の募集に出すと、二重応募の確かめが「同じ依頼主・似た題名」で止めることがある。中身（チャンネル・対象・納品物）が違うのを確かめてから出し、提案文に「別の募集にも提案しています」と1行書く（経歴がなくても同じ）
- 稼働を書く：「土日・夜も対応・メッセージは届いたらすぐ返します」（エージェントの強み＝24時間動ける）
- 実績が無いなら無いと書く。代わりに、自分で作った見本の URL と「初回は通常より下げた料金」を出す。🔴「無料で試作」「仮払い前にテスト1本」は書かない（CW 規約23条(31)が仮払い前の作業を禁止・ランサーズのガイドも提案にサンプルを付けない・開始前に作業しないよう求めている）
- 結び「よろしくお願いいたします」・最後の行に署名
- 送る前に tools/manner-mon.cjs（oubo）と tools/jisseki-mon.cjs を通す（呼び方は下の「下書きの穴を埋める」の手順6）

## 下書きの穴を埋める（mawasu.sh の段3の後・エージェントがやる）
段3の下書き（`<置き場>/oubo-bun/cw-<ID>.txt`）は、道具が宛名・名乗り・署名だけを埋めた形。中身の穴は templates/oubo-kihon.txt の5つが残る（作ったときに oubo-shitagaki.cjs が「🟡 埋める穴 5つ：{何をどうしたいご依頼か1文} {最初に確かめること} {作業の中身} {金額} {日数}」と出す）。
1. 募集の本文を開く：`https://crowdworks.jp/public/jobs/<ID>`（ログインなしで読める・門の cw-tantei.py が読むのと同じ頁）。「仕事の詳細」から「クライアント情報」の手前まで全部読む
2. 先に下の「応募できない募集の見分け方」に当てる。当たったら埋めずに見送りの記録を書いて次の下書きへ（1件止まっても、残りの下書きを読み続ける）
3. 依頼文に「応募時に答えてほしい項目」があれば、型より先にその項目を番号順で本文に足す（共通の決まり）
4. 穴を埋める

| 穴 | 何で埋めるか | 書かない物 |
|---|---|---|
| {何をどうしたいご依頼か1文} | 本文の依頼内容を自分の言葉で1文（何の・何を・どうしたいか） | 本文の丸写し |
| {最初に確かめること} | 作業の前にもらう物・見る物（今の状態・データの一部・権限など） | 本文に無い相手の事情 |
| {作業の中身} | 使う道具と作る物（「GAS で取り込みと集計を作り…」）。道具の指定が本文にあればそれ | 使ったことのない道具を「経験あり」と書く（型F） |
| {金額} | 本文の予算の帯の中の数字（docs/04 の「5 値段」）。本文は税込・入力欄は税抜（共通の決まり） | 「相談」のまま |
| {日数} | 最短の日数（既定は契約の当日〜2日後・共通の決まりの納期） | 相手の締切いっぱい |

5. 同じ名前の `.json` に `金額`（税抜の数字）と `納期`（`YYYY-M-D`）を書く。ランサーズは `計画の題名`（20字以内）と `計画` も。型の行が募集に合わないとき（新しく作る物に「今の状態を控えて」など）は、その募集に合う1文に直す。事実と違う行を型のまま残さない
6. 確かめる（3つとも通ってから、送る段＝オーナーの OK と `--go` へ）
   - 穴の残り：`grep -c '{' <下書き>` が 0
   - マナー・AI 臭さの門：`node -e "require('./tools/manner-mon.cjs')(require('fs').readFileSync('<下書き>','utf8'),'oubo')"`。通れば何も出ない。🔴 が1行でも出たら直す
   - 成果の言い方の門：`node -e "require('./tools/jisseki-mon.cjs')(['<下書き>'])"`。通れば何も出ない
7. 穴が残った物は送らない。道具の側も、`{…}` が1つでも残る下書きと、.json の金額・納期が空の下書きは段4の「送れる下書き」に数えない（tools/mawasu.sh の段4の実装）。`--go` でも送られないが、出したことにもならない（段6で出し漏れに数えられる・docs/12）

実測（2026-11-06・試しの置き場）：素のエージェントが作った下書き12件は、穴を埋めずに止まり、AI 臭さの検査で12件とも 🔴。🔴 の中身は12件とも「型の穴埋めが残っている」の1種だけで、ほかの 🔴 は0件だった。架空の募集（CSV の集計を GAS で自動にする）で5つの穴を埋めた下書き1件は、manner-mon・jisseki-mon とも何も出さずに通った（n=1。本物の募集で埋めた物を通したのは未確認）。経歴なしでも再現：する（穴は募集の本文と自分の作り方だけで埋まり、経歴の行は無い）

## 応募できない募集の見分け方（穴を埋める前に）
門の cw-tantei.py が本文の語で落とすのは、定例・出社・営業・現地・勧誘の型・AI 不可・CW テックなど（実装の語の表）。経験年数・SES・年齢や地域・実績の提示・資格は門の語に入っていない（2026-11-06 に実装で確かめた）＝★のまま下書きまで来る。下書きを埋める前に、本文で見る。
見る所：題名と、「仕事の詳細」の中の【条件】【応募条件】【必須】【募集対象】【求めるスキル】【ご応募時のお願い】などの見出しの下（2026-11-06 の実物では【条件】と【ご応募時のお願い】に書かれていた）

| 当たり | 本文の書き方の例 | 判定 |
|---|---|---|
| 経験年数が必須 | 「実務経験のある方（3年以上）」「開発経験3年以上」 | 見送り（年数は作れない） |
| SES・人の紹介 | 「SES事業」「1人月対応可能な方」「スキルシート必須」・週の出社 | 見送り（スキルシートは職歴そのもの・人が出向く形） |
| 年齢・地域・国籍が条件 | 「20〜30代」「大阪の方」「日本国籍の方」 | 見送り（応募の時点で年齢・住所を書かせる型は docs/04 でも見送り。オーナーが満たすかを推して書かない） |
| 副業不可・専任 | 「副業不可」 | 見送り |
| 実績の提示が必須 | 「◯◯の実績のある方のみ」「実績 URL と成果の数字が無い方は不可」 | 見送り（docs/04） |
| 資格の保有が必須 | 「行政書士募集」など資格の名で人を募る | 見送り（持っていない資格は名乗れない） |
| 実機・体・場所が要る | 「iPhone の実機で確かめる」「現地で」 | 見送り（docs/04 の dekiru-mon の線） |
| 実績を「聞くだけ」 | 「実績をお知らせください」「ポートフォリオがあれば」 | 出してよい。「この組み合わせの納品実績はまだありません」と書き、この案件向けに作った見本の URL を添える（共通の決まり・下の「応募の前に見本を作って添える」） |

- 「歓迎」「尚可」「あれば」の欄にだけある条件は、見送りの理由にしない（必須の欄と分けて読む）。同じ本文に両方あるときは【条件】の側を採る（2026-11-06 の実例：「経験3年未満の方もご連絡ください」と書いた同じ本文の【条件】に「実務経験（3年以上）」があった）
- どちらとも読めて決められないときは見送りにし、理由に読んだ行を書く（後で数えて線を直す材料にする）
- 🔴 経歴は作らない。年数・職歴・取引先・資格・実績は、オーナーの問診票（docs/16）の答えに無い物は書かない。答えに経歴があっても、確かめた事実だけを1〜3行（docs/16 の穴の決まり）。無い経験を「あります」と書かない（docs/01 の絶対の線5）。型は経歴の行が無くても成り立つ

### 見送りの記録の書き方
```
python3 tools/settei.py tsuika <YYYY-MM-DD> クラウドワークス <ID> '<題名>' '' '' '見送り：<理由>（<本文の欄>：<読んだ語>）'
```
例：`'見送り：経験年数が必須（【条件】：実務経験3年以上）'`。列は7つ（日付・場・案件ID・中身・提示額・月額・状態）。ランサーズは場を「ランサーズ」。状態は「見送り」で始める（数える道具が頭の語で見るため）
書くと効くこと（実装と、2026-11-06 の試しの置き場での実測）
- 段6の dashi-more.py は、状態に「見送」を含む ID を出し漏れから外す（試し：下書き1件で「出し漏れ 1 件」rc=1 → 見送りの1行を足すと「出し漏れ 0 件」rc=0）
- 巡回（cw-junkai.py）と門（cw-tantei.py）は、記録にある ID を次の周から出さない（settei.py の kiroku_ids）
- tools/kyou-kazu.sh が、その日の「見送り」に数える（試し：「見送り 1件」）
- 下書きのファイルは消さなくてよい（記録の行で外れる）

## 型B Shopify の小さな修正
- 「公開中のテーマは触らず、複製したテーマで直し、プレビューで確かめてから公開」を必ず入れる（相手の店の表示を崩さない）
- 範囲を固定（直す箇所の一覧をもらう）・範囲外は作業の前に追加の額

## 型C 月額・継続の募集
- 相手の事業を1文で言い直す → 最初の1か月で何を出すか（週ごとの成果物）→ 報告の形（毎週テキスト）
- 定例ミーティングは「テキストの週報＋必要なら録画」で代えられるかを最初から書いておく（後で揉めない）

## 型D 動画・ショート動画
- 依頼の項目（年齢・経験年数・使える道具・週の本数・最短納期・修正回数・開始日・連絡の時間帯）を全部その順で
- 使っていない道具（例：Premiere Pro）は「ございません」と正直に書き、代わりに使う道具と納品の形（MP4・縦1080×1920 など）を書く
- 「テスト1本で水準に届くかご判断ください」で締める

## 型F「◯◯の使用経験（必須）」で、その道具をまだ使っていないとき
- その道具が無料なら、応募の前に入れて、募集の形に合わせた見本を1本（30秒で足りる）作る。作ってから「あります（使い始めて日は浅い）」と書く。使っていないのに「あります」とは書かない
- 参考動画・参考サイトが付いていたら、先に実物を開いて構成（前半・後半・見出し・字幕の位置）を確かめ、見本をその形に寄せる。⑩「確認しましたか」には見た中身を1行添える
- 解説動画（VOICEVOX＋絵＋テロップ）なら tools/mihon-douga.py で作れる（台本を1行1場面で書く・読みのカナが出るので読み間違いを直してから使う）
- 見本は公開の置き場に上げ、URL を応募文の「実績」の欄に書く
- 「作品を添付して応募」とあり、合う見本が無いとき：架空の題材で1枚作って添付し、出した後に両方の場のポートフォリオにも載せる（次の同じ型の募集で使い回せる）。コンペに出した物や依頼主の文言が入った物は見本に使わない。依頼主が挙げた納品の形式（Illustrator の .ai など）を持っていなければ、出せる形式を書いたうえで「必須なら作業前にご相談させてください」と書く（持っていない形式を出せるとは書かない）。経歴なしで再現：する
- 有料の道具（例：ゆっくり音声は作る側が年額の使用ライセンスを買う決まり）は、買う前にオーナーの OK を取る。OK までは無料の道具の募集だけに出す
- 実例（11/03）：応募0人の時点で見つけ、エンジンを入れて見本を作り、参考動画を確かめて応募するまで約30分。経歴なしでも再現：する

## 型G GAS が「実行時間の上限を超えました」で止まる改修
- 応募文に直し方を3つ書く：①参照データは最初に1回読み込んで使い回す ②書き込みはためて setValues で1回 ③5分で区切り「どこまで終わったか」を記録して時間主導のトリガーで続きから再開
- 型の実物：templates/gas-jikan-jougen.gs（偽のシート1,000行・1行1秒の時計で、4回に分かれて全行・順番どおり書けることを確かめた）
- 「直したら多いデータ・少ないデータの両方で最後まで通ることを確かめてから渡す」を必ず書く。経歴なしでも再現：する
- 撮影済みの動画（トーク・解説）の編集は tools/cut-jimaku.py で「無音を詰める→字幕の下書き→焼く」まで出せる。字幕は焼く前に必ず1文字ずつ直す（30秒の見本で 30.3→28.8秒・9行を確認）
- AI 動画の生成で見本を作るときは「高画質・横 16:9・1カット◯秒」を頼む文に必ず書く。書かないと安い作り手に回り、縦や低い解像度で届くことがある（11/04 実測：16:9・5秒で頼んだ3本が 720×406 横5秒・720×1280 縦8秒×2 でそろわなかった）。届いたら ffprobe で幅・高さ・秒を3本とも確かめてから編集に入る。経歴なしでも再現：する
- PDF の議事録・帳票をスプレッドシートへ転記する仕事は tools/pdf2tenki.py で「原文どおりに行へ分けて CSV（Excel で開ける）」まで出し、2通りの取り出し（pdftotext・pypdf）を1字ずつ突き合わせる。食い違い・化けの所だけ原文を目で見る。画像だけの PDF は止まる＝読み取り（OCR）を使う前に依頼主の了承を取る（経歴なしでも再現：する）

## 型H チラシ・パンフのコンペ（評価0件でも出せる・当たれば最初の評価）
- 選ぶ条件：「生成AI使用可」・納品が JPG／PDF／PNG（Illustrator の .ai 必須は見送り）・「本人確認／ランサーズチェック／評価が必要」の付いていない物・提案数が少ない物（0〜30件）。ロゴのコンペは提案が100件を超えやすく当たりにくい
- 作り方：HTML と CSS で1面ずつ組み、tools/chirashi-kakidasu.cjs で約300dpi の JPG と PDF に書き出す（B5 なら 182 257・A4 なら 210 297）
- 依頼主のサイトがあれば開いて色づかいを合わせる。ロゴの画像や写真は写さず、社名は文字で組む。絵は自分で描く（SVG の簡単な形で足りる）
- 依頼の「記載項目」を1行1項目で書いた紙を作って道具に渡す。1つでも欠けたら止まる。帯との重なり・紙の外へのはみ出し・「12月1日（月）」の曜日違いも止まる（11/04 自分の見本で曜日を2つとも外していた）
- 依頼に無い事実を足さない（「税込」・創業◯年・作業の中身など）。決まっていない日付は「◯月◯日」の空欄にし、提案文に「決まり次第入れます」と書く。割引の計算（通常×0.7＝特価など）は手で確かめる
- 対象の年代が上なら文字を大きく、金額は一番目立つ所に。提案文は「考えたこと」「修正・納品」の2つに分けて、キャッチの別案を2つ添える
- 実例（11/04）：B5両面の羽毛布団クリーニングのチラシ、提案0件の時点で見つけ、サイトの色を見て作り、記載11項目を機械で照らして出すまで約40分。経歴なしで再現：する（コンペは作品だけで選ばれる）

## 応募の前に見本を作って添える（11/04）
- 作れる物は「できます」と書き、その根拠をその場で作る：案件と同じ形の小さな物（動く頁・実行の記録・出た表）を作り、公開して URL を添える
- 見本には「動かした記録」を入れる：正常の道と、わざと壊した道（取れない時に理由を残して止まるか）の両方
- 書き方は「この案件向けに作った見本です」。お客様に納めていない物を「納品実績」とは書かない
- 経歴なしでも再現するか：する（見本は誰でも作れる・経歴の代わりの根拠になる）。返事の率に効くかは未測（11/04 から付けた応募と付けない応募を分けて数える）
