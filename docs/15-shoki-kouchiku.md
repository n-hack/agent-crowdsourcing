# 15 初期構築（人がやる所）

この章は、オーナー（人）がこの紙のとおりに押せば、誰がやっても同じ状態になるように書いてあります。
人がやるのは、登録・本人確認・受け取り口座・連絡の受け口の用意だけです。済んだかどうかはエージェントが1行打って確かめます。各段の終わりの「確かめ」の行がそれです。

## 守ること（先に読む）
- アカウントは本人が自分の手で作る。どの場も規約で「登録は本人だけ・1人1アカウント」（docs/01）。エージェントは登録の画面を押さない
- 登録は、エージェントが自動で操っているブラウザではなく、人が手で開いたブラウザで行う（自動で操った形跡のある登録は止められやすい）。下の段0の Chrome を人が手で使うのは問題ない
- 人間確認（画像の文字・パズル）・電話の確認・身分証の撮影・ビデオ通話は人がやる
- パスワード・鍵は、エージェントとのやり取りに貼らない。鍵のファイルはこのリポジトリの外に置き、置いた道だけを config/profile.json か環境変数に書く
- お金が出る登録（有料の会員・前払いの枠）は、この紙には入れていない。必要になったらオーナーが判断する

## 段0 エージェントが使う Chrome を決める
エージェントは、ログインしたままの Chrome に「つなぐ」形で場の頁を読み書きします。そのための Chrome を1つ、ほかの用事と分けて用意します。

人がやること
1. Mac のターミナルで次を打つ（置き場の名前は自由。ふだん使いの Chrome とは別の置き場にする。Chrome は既定の置き場のままだと、つなぐ口が開かない）
   ```
   "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --remote-debugging-port=9222 --user-data-dir="$HOME/cs-chrome"
   ```
2. 開いた Chrome で、段1以降のログインを全部済ませる（この Chrome に残ったログインをエージェントが使う）
3. ポートを 9222 以外にしたときは、config/profile.json の「ブラウザ」の「CDPのポート」に書く

確かめ（エージェント）
```
curl -s -m 5 http://127.0.0.1:9222/json/version | grep -c '"Browser"'
```
1 なら開いている。0 か何も出なければ Chrome が起きていないか、口のポートが違う。

## 段1 専用のメールと予定（Google）
場からの通知・面談の招待・採用の連絡が届く受け口です。仕事専用のアドレスを1つ作り、場の登録はすべてこのアドレスで行います。

どちらかを選ぶ
| 形 | エージェントが受信箱と予定を読む方法 | 向き |
|---|---|---|
| A. Google Workspace（独自ドメインのメール） | サービスアカウントに代理で読ませる（tools/henji-mihari.py・mendan-waku.py がそのまま動く） | おすすめ |
| B. 無料の Gmail（末尾が gmail.com のアドレス） | サービスアカウントの代理読みが使えない。段0の Chrome で Gmail を開いて、エージェントが画面で読む | 費用をかけない時 |

B を選んだときは A の手順は飛ばしてよい。メールの見張りは「未設定」と出たまま（rc=4）になり、エージェントは受信箱を画面で開いて見る（docs/01 の「巡回のたびに受信箱をじかに開く」と同じ）。

### A の手順（Google Workspace）
画面の名前は Google の公式ヘルプの表記に合わせています。この紙を書いた日には管理画面そのものは開いていないので、名前が少し違うことがあります。
1. 管理コンソールで、仕事専用のユーザーを1つ作る（例 `shigoto@<自分のドメイン>`）。カレンダーはこのユーザーのものを使う
2. Google Cloud コンソールでプロジェクトを1つ作り、「Gmail API」と「Google Calendar API」を有効にする
3. 同じプロジェクトで「サービスアカウント」を1つ作り、鍵（JSON）を作って Mac に保存する。置き場はこのリポジトリの外（例 `~/.cs-keys/`）。保存したら `chmod 600 <鍵のファイル>`
4. 鍵の中の client_id（数字の並び）を控える
5. 管理コンソール →「セキュリティ」→「アクセスとデータ管理」→「API の制御」→「ドメイン全体の委任」→「新しく追加」。クライアント ID に4の数字、スコープに次の2つを入れて承認する
   ```
   https://www.googleapis.com/auth/gmail.readonly,https://www.googleapis.com/auth/calendar.readonly
   ```
   どちらも「読むだけ」です。エージェントはこの鍵でメールを送ったり予定を書き換えたりできません
6. config/profile.json の「メールの見張り」に鍵の道と受信箱、「面談の予定」に鍵の道とカレンダーのメールを書く（エージェントに頼んでよい。鍵の中身は渡さず、置いた道だけ伝える）
7. エージェントの側で `pip install google-auth requests`

確かめ（エージェント）
```
python3 tools/henji-mihari.py; echo rc=$?
python3 tools/mendan-waku.py; echo rc=$?
```
| rc | 意味 |
|---|---|
| 0 | つながった（henji-mihari は初回は見た印を付けるだけで鳴らない） |
| 1 | つながった・新しい便がある（henji-mihari） |
| 3 | 鍵はあるが読めない（委任のスコープの入れ忘れ・API の有効化忘れが多い） |
| 4 | 設定が無い・鍵の道が違う |

### Google Meet
面談に出るのは人です（docs/01）。面談が決まったら、人が自分のカレンダーで予定を作り「Google Meet のビデオ会議を追加」を押して URL を付けます。エージェントは空き枠を出す（mendan-waku.py）と、面談の前の1枚（docs/13）を作るところまで。
エージェントに予定まで作らせたいときは、5のスコープに `https://www.googleapis.com/auth/calendar.events` を足す必要があります。このリポジトリの道具はまだ予定を作りません。

## 段2 場の登録（日本）
docs で使っている場です。上から順に効きます（docs/14 の逆算は CW とランサーズが主）。

| 場 | 登録の入口 | 登録の形 | 確かめ（エージェント） |
|---|---|---|---|
| クラウドワークス | crowdworks.jp の「会員登録」 | 受注者として登録。個人・法人どちらも可（docs/01） | `node tools/shoki-kakunin.cjs cw` |
| ランサーズ | lancers.jp の「会員登録」 | 個人・法人どちらも可 | `node tools/shoki-kakunin.cjs lancers` |
| AIクラウドワークス | クラウドワークスのアカウントで入る | 別の登録は無い（CW のログインで開ける） | `node tools/shoki-kakunin.cjs aicw` |
| SOKUDAN | sokudan.work の登録 | 副業・業務委託の場。返事は少ない（docs/02） | `node tools/shoki-kakunin.cjs sokudan` |
| Workship | goworkship.com の登録 | 応募は「気になる！」だけで、プロフィールが応募文の代わり（docs/02） | `node tools/shoki-kakunin.cjs workship` |
| スキルシフト | skill-shift.com の登録 | 副業の場。返事は少ない（docs/02） | `node tools/shoki-kakunin.cjs skillshift` |

人がやること（どの場も同じ）
1. 段0の Chrome を手で開き、登録の頁へ行く
2. メールは段1の専用アドレス。名前・住所・電話は本人のもの（名義は後で受け取る口座と合わせる。法人で受けるなら法人名で）
3. 届いたメールの確認のリンクを押す
4. ログインしたまま Chrome を閉じない（閉じても、同じ置き場で起こせばログインは残る）
5. 表示名を決める欄があれば、問診票（docs/00）の「表示名」と同じにする

確かめの読み方
- `✅ ◯◯ ログイン済み` … 段0の Chrome でその場にログインできている
- `🔴 ◯◯ ログインの頁に戻された` … 未登録か、ログインが切れている。人がもう一度ログインする
- `🔴 ブラウザ（…）につなげない`（rc=3）… Chrome が起きていないか、混んでいて20秒でつながらなかった。少しおいてもう一度打ち、続くなら段0へ戻る（「未登録」とは違う。試した日に1回、つながらずに次の回で通った）
- まとめて見るときは `node tools/shoki-kakunin.cjs all`（1つでも 🔴 なら rc=1）

## 段3 本人確認・NDA・電話確認
実績0のうちは、ここを先に済ませると見える仕事が増えます（NDA 付きの仕事は締結した人にしか見えない・ランサーズチェック済みの人に限る依頼がある・docs/04）。どれも書類の撮影や電話が要るので人がやります。

| 場 | 済ませる物 | 場所 |
|---|---|---|
| クラウドワークス | 本人確認書類の提出・NDA（秘密保持契約）の締結 | プロフィールの頁（crowdworks.jp/profile）に項目が並ぶ |
| ランサーズ | 本人確認・機密保持確認・電話確認・ランサーズチェック | 自分のプロフィールの頁の頭に4つの印が並ぶ |
| SOKUDAN・Workship・スキルシフト | 求められたら | 各場の案内に従う |

確かめ（エージェント）
```
node tools/shoki-kakunin.cjs cw
node tools/shoki-kakunin.cjs lancers
```
- クラウドワークスは「本人確認書類提出 未登録」のように、項目名の後ろに状態の語が出る。状態の語が頁に出ていない項目は「─（状態の語が出ていない）」と出る＝未提出とは限らないので、人が頁を目で見る
- ランサーズは印ごとに「済」か「未（緑の印なし）」と出る（試した日は4つとも済のアカウントだけで、「未」の出方はまだ見ていない）
- 審査中のあいだは「済」にならない。1〜3営業日おいてもう一度打つ

| 場 | 場所 |
|---|---|

## 段5 海外の場（任意）
docs/11 の続きです。日本の場で回り始めてから足す順番です（docs/14）。どちらも本人確認は人が1回だけやります。

### Fiverr（出品して待つ型）
- 規約で AI の使用は可。ただし依頼主が「AI なし」を求めたら従う。自動の返信は AI と名乗る。AI で作った映像で本人確認をするのは禁止
- 手数料は売上の20%（チップにもかかる）
- 応募はしない。出品（Gig）を作って注文を待つ型＝ランサーズのパッケージと同じ骨（docs/07）
- 人がやること：登録 → 最初の出品を出すと、電話番号の確認 → 身分証かセルフィーの確認（外部の会社・5回まで）を求められる。出品の中身（題・説明・値段）はエージェントが下書きし、人が押す
- プロフィールの写真は会社のロゴでもよい（docs/11）
- 確かめ（エージェント）：`node tools/shoki-kakunin.cjs fiverr`

### Upwork（応募する型・決まりが一番きつい）
- 規約で禁止されていること（2026-08-13 版の規約の PDF で確かめた）
  - 本人がその場で指示しない、自動の案件選びと応募（5.9）
  - API や MCP を通して AI が書いた文を、AI だと開示せずに送ること（9.7）
  - アカウントの共有
- だからこのリポジトリでは：案件を探す・選ぶ・応募文の下書きまではエージェント、**応募の最後の「送る」を押すのは人**。API・MCP の口は使わない（使うなら AI の開示が要り、本人として送る決まり（docs/06）とぶつかる）
- 🟡 未確認：画面の操作で送る文に AI の開示が要るかの原文、画面の操作でのアカウントの共有・自動化を禁じる条文。どちらも本体の頁が開けず（403）、この紙では確かめていない。始める前に人が規約の本文を読む
- 人がやること：登録 → 身分証の提出＋短いビデオ通話か写真（求められてから7日以内）→ プロフィールの写真は顔が必須（docs/11）→ 出金方法の登録（円で日本の銀行へ直接出金できる・docs/11）
- 応募には Connects（1個 $0.15・無料は月10個）を使う。買うかどうかはお金の判断なので人が決める
- 確かめ（エージェント）：`node tools/shoki-kakunin.cjs upwork`

## 段6 連絡ツール（Chatwork・Slack）
契約の後、依頼主から「Chatwork か Slack に入ってください」と言われることがあります。場の中の連絡は、契約の前と、サービス外連絡の申請が承認される前は場のメッセージだけです（CW 規約9条8項・docs/01）。ここは契約の後に使う物の用意です。
🔴 このリポジトリには、Chatwork・Slack を読んだり送ったりする道具はまだありません。下はエージェントが本人として読めるようにするための鍵の用意と、つながったかの確かめまでです。

### Chatwork
1. 段1の専用アドレスで Chatwork のアカウントを作る（無料のプランで始められる。ただし無料は組織の外の人とのコンタクトが20人まで）
2. 「サービス連携」から API トークンを発行する。勤め先などの組織契約の中のアカウントだと、組織の管理者への利用申請が先に要る
3. トークンは、エージェントが動く Mac の環境変数 `CHATWORK_TOKEN` に入れる（シェルの設定ファイルなど。リポジトリには書かない）
4. 依頼主の部屋には、依頼主の招待（コンタクトの承認か招待のリンク）で入る。API のために依頼主の承認は要らない。依頼主が組織の外の人とのやりとりを禁じている設定なら、依頼主の管理者に許可の設定をしてもらう

確かめ（エージェント）
```
curl -s -H "X-ChatWorkToken: $CHATWORK_TOKEN" https://api.chatwork.com/v2/me | python3 -c "import json,sys;d=json.load(sys.stdin);print('✅ つながった' if 'account_id' in d else '🔴 ' + str(d.get('errors')))"
```
トークンも中身も画面に出さず、つながったかだけを出します。API は1人あたり5分に300回まで（超えても知らせは来ない）。

### Slack
Slack は依頼主のワークスペースに招待されて入ります。エージェントが本人として読むには、本人のユーザートークンが要ります。
- 正式メンバーで招待されたとき：自分で作った Slack アプリ（ユーザートークンの権限だけ・読む・送る・人の名前）を、そのワークスペースに入れて「許可する」を押す。依頼主が「アプリは承認制」なら、依頼主の管理者の承認が1〜2回要る。「事前承認済みアプリだけ」の設定なら入れられない
- ゲストで招待されたとき：ゲストはアプリを入れられない。正式メンバーに変えてもらうか、Slack コネクト（こちらのワークスペースの本人と DM）にしてもらう。どちらも無理なら、画面で人が送る（エージェントは下書きまで）
- 自分で作ったアプリを依頼主のワークスペースに入れるには、アプリの管理画面で「公開配布」を有効にする必要がある（Marketplace の審査とは別）。その前に、認可の戻り先の HTTPS の頁が1つ要る
- Slack の API の規約では、組織の外の人のワークスペースで使うときは、その組織から明示の許可をもらう決まり。依頼主には「私が参加しているチャンネルと私宛ての便を読み、私の名前で返信する」と範囲を書いてお願いする
- トークンは環境変数 `SLACK_USER_TOKEN`（ワークスペースが複数になったら名前を分ける）

確かめ（エージェント）
```
curl -s -H "Authorization: Bearer $SLACK_USER_TOKEN" https://slack.com/api/auth.test | python3 -c "import json,sys;d=json.load(sys.stdin);print('✅ つながった：' + d.get('team','')) if d.get('ok') else print('🔴 ' + d.get('error',''))"
```
