# 12 1日の回し方（骨格と道具）

1周 ＝ 巡回（新着を集める）→ 門（分野・勧誘・二重応募）→ 応募文 → 応募 → 返事の見張り → 返事 → 出し漏れの検算。
入口は `bash tools/mawasu.sh`（既定は下書きまで・`--go` のときだけ送る）。1周は長い（CW の応募ごとの部屋を全部開くため）ので裏で回し、終わるたびに呼び直す。

## 始める前に（1回だけ）
1. `node tools/nhack-mon.cjs` が ✅ になること
2. `config/profile.example.json` を `config/profile.json` に写して直す
   - 名乗り・署名・名前・会社名・メール … 応募文と返事に入る（見本の「◯◯」のままだと下書きの道具が止まる）
   - 自分の名前の印 … 返事の見張りが「最後に書いたのが自分か」を見分ける語（会社名・名前）
   - 自社の依頼主ID … 自分の会社が出した募集に応募しないための依頼主の表示名
   - 置き場 … 記録・下書き・巡回の結果を置く所（既定 `~/cs-data`・リポジトリの外。環境変数 `CS_DATA` が先）
   - ブラウザ … ログイン済みの Chrome をつなぐ先（`--remote-debugging-port=<CDPのポート>` で起こす。環境変数 `CS_CDP_URL`／`CS_CDP_PORT` が先）。ほかの人・ほかの作業と同じブラウザを取り合わない
   - 巡回の語 … CW の新着を引く語（"" は語なしの新着一覧）。取る分野は config/bunya.json
   - メールの見張り・面談の予定 … Google Workspace のサービスアカウント（受信箱を代理で読む・予定の空きだけ読む）。未設定なら、その段は「見ていない」と出す（0件とは言わない）
3. 要る物：node と playwright（`npm i -g playwright`）・python3・メールと予定を使うなら `pip install google-auth requests`

## mawasu.sh の段
1. 巡回（cw-junkai.py）
2. 門（cw-tantei.py）… ★ だけが次へ
3. 応募文（oubo-shitagaki.cjs）… 下書きを作るだけ。エージェントが募集の本文を読み、穴（{…}）を埋め、同じ名前の .json に金額と納期を書く
4. 応募 … 既定は送らない。`--go` のとき、穴が埋まり金額・納期のある下書きで、記録に応募の無い物だけ cwapply.cjs で送る（門で止まった物は数えて次へ）
5. 返事の見張り（henji-mihari.py → cw-thread-check.cjs → 応募一覧の状態）… `--no-browser` ならログインの要る段は飛ばし「見ていない」と書く
6. 出し漏れの検算（dashi-more.py）

どの段でも道具が落ちたら、段の名前と理由を出して rc=2 で止まる（落ちたのを「0件」と同じに見せないため）。要対応（新しい返事・要返信・状態の変化・出し漏れ）があれば rc=1。全部の記録は `<置き場>/mawasu.log`。
🔴 外へ送るのは `--go` のときだけ。送る前にオーナーの OK の決まり（docs/01）を確かめる。
