# 12 1日の回し方（骨格と道具）

1周 ＝ 巡回（新着を集める）→ 門（分野・勧誘・二重応募）→ 応募文 → 応募 → 返事の見張り → 返事 → 出し漏れの検算。
入口は `bash tools/mawasu.sh`（既定は下書きまで・`--go` のときだけ送る）。1周は長い（CW の応募ごとの部屋を全部開くため）ので裏で回し、終わるたびに呼び直す。

## 始める前に（1回だけ）
1. `node tools/nhack-mon.cjs` が ✅ になること
2. `config/profile.example.json` を `config/profile.json` に写して直す
   - 名乗り・署名・名前・会社名・メール … 応募文と返事に入る（見本の「◯◯」のままだと下書きの道具が止まる）
   - 自分の名前の印 … 返事の見張りが「最後に書いたのが自分か」を見分ける語（会社名・名前）
   - 自社の依頼主ID … 自分の会社が出した募集に応募しないための依頼主の表示名
   - 置き場 … 記録・下書き・巡回の結果を置く所（既定 `~/cs-data`・リポジトリの外。環境変数 `CS_DATA` が先）
   - ブラウザ … ログイン済みの Chrome をつなぐ先（`--remote-debugging-port=<CDPのポート>` で起こす。環境変数 `CS_CDP_URL`／`CS_CDP_PORT` が先）。ほかの人・ほかの作業と同じブラウザを取り合わない
   - 巡回の語 … CW の新着を引く語（"" は語なしの新着一覧）。取る分野は config/bunya.json
   - メールの見張り・面談の予定 … Google Workspace のサービスアカウント（受信箱を代理で読む・予定の空きだけ読む）。未設定なら、その段は「見ていない」と出す（0件とは言わない）
3. 要る物：node と playwright（`npm i -g playwright`）・python3・メールと予定を使うなら `pip install google-auth requests`

## mawasu.sh の段
1. 巡回（cw-junkai.py）
2. 門（cw-tantei.py）… ★ だけが次へ
3. 応募文（oubo-shitagaki.cjs）… 下書きを作るだけ。エージェントが募集の本文を読み、穴（{…}）を埋め、同じ名前の .json に金額と納期を書く
4. 応募 … 既定は送らない。`--go` のとき、穴が埋まり金額・納期のある下書きで、記録に応募の無い物だけ cwapply.cjs で送る（門で止まった物は数えて次へ）
5. 返事の見張り（henji-mihari.py → cw-thread-check.cjs → 応募一覧の状態）… `--no-browser` ならログインの要る段は飛ばし「見ていない」と書く
6. 出し漏れの検算（dashi-more.py）

どの段でも道具が落ちたら、段の名前と理由を出して rc=2 で止まる（落ちたのを「0件」と同じに見せないため）。要対応（新しい返事・要返信・状態の変化・出し漏れ）があれば rc=1。全部の記録は `<置き場>/mawasu.log`。
🔴 外へ送るのは `--go` のときだけ。送る前にオーナーの OK の決まり（docs/01）を確かめる。

## 裏で回したときの終わりの受け方
1周は数分〜数十分かかる（巡回で100件を超える募集の頁を1件ずつ開くため）。前で待たずに裏で回し、終わりは知らせで受ける。待つための繰り返し（until・while・sleep）は書かない。
```
bash tools/mawasu.sh --no-browser > "<置き場>/mawasu.out" 2>&1; echo "rc=$?" >> "<置き場>/mawasu.out"
```
Claude Code なら Bash の裏で回す指定（run_in_background）で打つ。終わると知らせが来るので、そこで `<置き場>/mawasu.out` の最後の数行を読む。

rc の意味（tools/mawasu.sh の実装から）
| rc | mawasu.log の最後の行 | 意味と次の手 |
|---|---|---|
| 0 | `MM-DD HH:MM 1周 終わり：要対応なし` | 1周が通った。次の周を呼ぶ |
| 1 | `MM-DD HH:MM 1周 終わり：要対応あり（上の 🔔 を全部返してから次の周へ）` | 新しい返事・要返信・状態の変化・出し漏れがある。mawasu.out の 🔔 の行の中身を全部返してから次の周 |
| 2 | `MM-DD HH:MM 🔴 段「◯◯」で止まった：<道具> rc=<数> ／ <理由>` | その段の道具が落ちた。理由を読んで直す。それより後ろの段は回っていない（「0件」ではない） |
| 2 | （mawasu.log に新しい行が無い） | 呼び方の誤り（使い方が出る）か、設定が読めない（「🔴 設定が読めない」）。mawasu.out を読む |
| 上のどれでもない | 最後の行が段の途中（`1 巡回 ✅ …` など）のまま | 途中で殺された（時間の上限・Mac の再起動など）。終わっていない＝結果は出ていない。もう一度回す |

mawasu.log は周をまたいで足されていくので、回す前の行数を控え、それより後ろの行だけを読む（`wc -l < <置き場>/mawasu.log`）。前の周の「終わり」の行を今回の終わりと読まない。

## 送る道具の結果が見えないときは、送り直す前に記録を見る
応募・返事の道具（cwapply・teian・cwreply など）の出力を grep や head で絞ると、成功の行（`✅ 頁に載った`・`📝 記録に1行足した proposal …`）が落ちて「送れたか分からない」ことがある。そのまま同じ道具をもう一度打つと、二重応募・二重送信になる。
1. まず記録を見る：`grep "<ID>" <置き場>/oubo-kiroku.tsv`（応募）・相手の部屋を読む道具で最新の便（返事）
2. 記録に行があれば送れている。無ければ、道具がまだ動いていないか（`pgrep -f "<道具> <ID>"`）を見てから、動いていなければ打ち直す
3. 道具の出力は絞らずに全部ファイルへ書き、最後の15行を読む（`> out.log 2>&1; tail -15 out.log`）
（2026-11-06 実例：結果の行を grep で落とし、1回目で通っていた応募に2回目を打ちかけた。経歴がなくても同じ）

## playwright が入っているかの確かめ
ブラウザを使う段（ランサーズの巡回・CW の部屋の見張り・応募・返事・tools/shoki-kakunin.cjs）は playwright が要る。道具と同じ探し方（環境変数 PLAYWRIGHT_PATH → 普通の require → `npm root -g` の下）で確かめる1行：
```
node -e "require('./tools/settei.cjs').playwright(); console.log('✅ playwright あり')"
```
🔴 が出たら `npm i -g playwright` を打ち、もう一度。ブラウザ本体はダウンロードしなくてよい（ログイン済みの Chrome につなぐ形なので）。
ログイン済みの Chrome の起こし方と、各場にログインできているかの確かめは docs/15（段0・段2）。
