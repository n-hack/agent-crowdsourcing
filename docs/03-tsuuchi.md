# 03 通知の読み方 ── 題だけで「決まった」と読まない

2026-11-03 に、ランサーズの「当選者が決定されました」を「採用された」と読み違えかけた（実際は落選）。通知欄は場ごとに意味が違う。決まったかどうかは、下の「確かめる場所」を開いて決める。

## 通知の題と本当の意味
| 場 | 通知の題 | 本当の意味 | 確かめる場所 |
|---|---|---|---|
| ランサーズ | 仕事の進行「◯◯の当選者が決定されました」 | 選定が終わった知らせ。**当選した人にも外れた人にも同じ題**で届く | メール「提案したプロジェクトの選定が終了しました」の本文（「選ばれませんでした」なら落選）／仕事管理 → 作業（/mypage/tasks）に出れば当選 |
| ランサーズ | 提案を受け付けました | 自分の提案が出ただけ | ─ |
| ランサーズ | 「レギュラーにランクアップ」 | ランクの変化（仕事ではない） | ─ |
| CW | お知らせ「◯◯に新しい条件が提示されました」 | 相手が金額・納期を出した＝契約の一歩手前。返事が要る | そのスレッドと 契約一覧（/e/contracts） |
| CW | 応募・スカウトが辞退されました | 相手が断った（か自分が辞退した） | メッセージ一覧の「辞退」 |
| CW | ◯◯について相談がありました | 相手からの最初の便（勧誘の型が多い） | 開いて tools/kanyu-mon.cjs を通す |
| CW | 契約一覧に行が出る | **ここに出たら決まり** | /e/contracts |
| SOKUDAN | チャット部屋の新しい便 | 相手からの連絡 | /project_chat_rooms |
| スキルシフト | 「お申し込み有難うございます」 | 自動の受付（決まりではない） | /member/message-list の企業からの本文 |
| Workship | 「スカウトはありません」が消える | スカウトが来た | /like/from_company |

## 届く場所の一覧（見張る所）
| 場 | 場所 | 何が来るか | 見張り方 |
|---|---|---|---|
| CW | 上の「メッセージ」（最新10件・行ごとに「返信済み」の印） | やり取り・相談・面談の連絡 | 「返信済み」が無い行は返すまで毎回鳴らす（状態で見る） |
| CW | /messages（受信箱・全部） | 同上 | 最新の頭が変わり、こちらの文でない行を鳴らす |
| CW | 上の「お知らせ」 | 契約・条件の提示・採用・評価 | 新しい番号を鳴らす |
| CW | メール（no-reply@crowdworks.jp） | 上の全部 | 件名で「選定・当選・落選・発注・仮払い・採用・依頼が届」を拾い、本文で当落を添える |
| ランサーズ | メッセージ | 提案のやり取り | 未読は読むまで毎回鳴らす |
| ランサーズ | /notification | 招待（直接の依頼）・仕事の進行・評価 | 新しい番号を鳴らす |
| SOKUDAN | /project_chat_rooms | 案件ごとのチャット | 部屋の最新の差分 |
| Workship | /message・/like/from_company | メッセージ・スカウト | 一覧の差分（相対時刻は外して比べる） |
| スキルシフト | /member/message-list | 選考の連絡 | 一覧の差分（自動の受付の文は鳴らさない） |

## 見張りで踏んだ穴
- 「前回からの差分」だけで鳴る作りだと、見張りが止まっている間に来た便は二度と鳴らない → 起こし直したら、まず「状態」（CW の返信済み・ランサーズの未読）で取りこぼしを拾う
- 見張りが止まって出した行は全部返してから立て直す（1通だけ返して、もう1通を1時間20分放置した実例あり）
- CW の応募には「既読」の印が無い。読まれたかは分からない前提で動く
