# 16 プロフィールとポートフォリオを用意する（問診票から機械的に埋める）

どのエージェントがやっても同じ物ができるように、プロフィールの文とポートフォリオの見本を型にした。オーナーがするのは問診票に答えることだけ。
売れている人の型（並べ方・題の付け方）と字数の上限の実測は docs/07、経歴の「書いてよい／書かない」の線は templates/keireki.md にある。ここでは重ねて書かない。
分野は AI の導入・業務の自動化・開発・データ入力とリスト作成（templates/keireki.md の Web・SNS・動画の例は前の分野の物）。

## 置いた物
| 置き場 | 中身 |
|---|---|
| templates/profile/monshinhyou.md | オーナーが書く問診票。欄ごとに入る穴・空でよいか・オーナーへ聞く1通 |
| templates/profile/cw.txt | クラウドワークスの自己PR（1行目はキャッチフレーズの欄へ） |
| templates/profile/lancers.txt | ランサーズの自己紹介（URL を書かない形） |
| templates/profile/sokudan-workship.txt | SOKUDAN・Workship の自己紹介（応募文の代わりになる） |
| templates/profile/fiverr.txt | Fiverr の Gig の題・説明・プロフィール（英語） |
| templates/profile/upwork.txt | Upwork の題・概要（英語） |
| templates/portfolio/01〜05 | 見本5本（会社リストの CSV・Excel の自動集計・FAQ の自動返答・文字起こしと議事録・データ取得の小道具） |
| [samples/](../samples/) | 見本のうち 01・02・03 の実物（架空の題材で作って動かした物・出力を各 README に貼ってある） |

## 手順（エージェント）
1. オーナーに問診票の1通（monshinhyou.md の末尾）を送り、答えを受け取る。答えはリポジトリの外か .gitignore された置き場に置く
2. ポートフォリオの見本を先に作る（templates/portfolio/ の「作り方」をそのまま自分に渡す）。公開の頁に置き、一覧の頁の URL を {見本のURL} に使う
3. 場の型の {穴} を問診票の答えで埋める。空でよい欄が空なら、その穴がある行ごと消す。空でよくない欄が空なら作らずに聞き直す
4. 字数を数える（下の表）。CW は改行を2字で数える
5. 門を通す：`node -e "require('./tools/manner-mon.cjs')(require('fs').readFileSync('<埋めた文>','utf8'),'oubo')"` と、jisseki-mon.cjs（成果の言い方）。🔴 が1つでも出たら直す
6. オーナーがログインしたブラウザで場の編集画面に入れる。保存したら公開の頁を開き、字が切れていないか・題名が二重になっていないか（ランサーズの「ました」）を目で確かめる
7. 応募の前に、その募集が求める語がプロフィールに入っているかを見て、無ければ「できること」の行に足す（Workship は応募文の欄が無く、プロフィールだけで見られる・docs/02）

## 穴の決まり
- 型の `{穴}` と問診票の欄は1対1。問診票に無い穴は {見本のURL} だけで、これはエージェントが埋める
- 空でよい欄は {会社名}・{経歴があれば1〜3行}・{名前のローマ字}・{料金の下限ドル}（後ろ2つは海外の場を使わないときだけ）
- 経歴が空でも文が成り立つように書いてある。経歴があれば確かめた事実だけを1〜3行で入れる（無い年数・実績・取引先・金額の実績を作らない）
- 埋めた後に `{` が残っていたら manner-mon が 🔴（型の穴埋めが残っている）を出す。それで止める

## 場ごとの違い
| 場 | 字数 | URL | 言語 | 気をつける所 |
|---|---|---|---|---|
| クラウドワークス | 自己PR 1024字・改行は2字（docs/07 の実測） | 書ける | 日本語 | 1行目はキャッチフレーズの欄に入れ、本文から外す |
| ランサーズ | 自己紹介 1000字（docs/07） | 書けない | 日本語 | 見本はポートフォリオの欄へ。題名は「〜を作成し」で止める |
| SOKUDAN・Workship | 上限は未確認（入れる画面で数える） | 未確認 | 日本語 | 定例・週の時間で働く募集が多い（docs/02）。成果物で区切ること・進み具合は文章で送ることを先に書いてある |
| Fiverr | 上限は未確認（入れる画面で数える） | 未確認 | 英語 | 依頼主が「AI なし」と言えば従う決まり（docs/11）。自動の返事は AI と名乗る決まりがあるので、返事は自動の返信の機能に任せない |
| Upwork | 上限は未確認（入れる画面で数える） | 未確認 | 英語 | 顔写真が要る（docs/11）。名前は本名で出る |

## 写真・アイコンの決め方
| 場 | 決め方 |
|---|---|
| Upwork | 本人の顔写真が必須（docs/11）。問診票で「顔写真を出せない」なら Upwork は使わない |
| Fiverr | 会社のロゴでもよい（docs/11）。本人確認は身分証と本人の写真で、AI で作った映像を使うのは禁止 |
| クラウドワークス・ランサーズ・SOKUDAN・Workship | 顔写真か、会社のロゴ・屋号の文字だけの図。顔を出さないなら図にする |

共通の線
- AI で作った顔・他人の顔を、本人の顔として使わない。顔を出さないときは「人に見えない図」（ロゴ・屋号の文字・分野を表す単純な図）にする
- 顔写真は明るい所で正面・背景は無地。オーナーに撮ってもらう（エージェントは撮れない）
- 場をまたいで同じ図を使う（同じ人だと分かるように）
- 画像を作るときは、使った道具の使い方の条件（商用で使えるか）を先に読む（docs/07）

## ポートフォリオの見本（5本）
実物は [samples/](../samples/) にある（01 [会社リストの CSV](../samples/01-kaisha-list-csv/)・02 [Excel の自動集計](../samples/02-excel-shuukei/)・03 [FAQ の自動返答](../samples/03-faq-jidou-henji/)）。04・05 はまだ型だけ。

| 見本 | 見せたい所 |
|---|---|
| 01 会社リストの CSV | 出どころの利用規約を確かめてから取る・数え方つきで渡す・個人の連絡先を集めない |
| 02 Excel の自動集計 | 元の合計と表の合計が合わなければ止まる |
| 03 FAQ の自動返答 | FAQ に無い金額・言い切りを式で止める（AI に任せきらない） |
| 04 文字起こしと議事録 | 決まったこと・宿題を拾えたかを数えて見せる |
| 05 データ取得の小道具 | 頁の形が変わったら空の表を出さずに止まる |

5本に共通の決まり
- 題材は全部架空。頁の頭とポートフォリオの説明文に「見本として作った物（架空の題材）」と書く
- 実績・お客様の名前・納品の件数・売上の数字を作らない。金額の欄が要る場では「同じ規模をお受けする場合の目安」と書く
- 題は「業種＋目的」の形（docs/07）。ランサーズの題名の欄は「〜を作成し」で止める
- 正常な回と、わざと壊して止まった回の両方の記録を見せる（止まるのが売りになる）
- 各ファイルの「説明文」の塊がそのまま相手の目に入る文。ここも manner-mon と jisseki-mon を通す

## 相手が読む文の書き方
- 本人の「私」で書く。自分の側を「弊社の担当者」「担当の者」「代表の◯◯」など別の人に書かない
- 記号を飾りに使わない・箇条書きを重ねない・褒めすぎない・「させていただきます」を重ねない・絵文字と Markdown（# と ** と - の行頭）を入れない。型の ▼ の見出しは CW 上位の型を写した物で、5つまでにしてある（6つ以上で manner-mon が 🟡）
- 作業に AI の道具を使うことは書いてよい。自分が AI だと書く文は manner-mon が止める

## 見ていない範囲
- SOKUDAN・Workship・Fiverr・Upwork の字数の上限と URL の可否は、このリポジトリでは測っていない（入れる画面で確かめる）
- 型の文が選ばれやすいかは、まだ数で測っていない（docs/08 に足す）
- 経歴なしでも再現するか：する（文は経歴の行が無くても成り立つ）。Upwork だけは顔写真が要るので、顔を出せないオーナーでは再現しない
