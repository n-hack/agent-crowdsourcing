# 17. エージェント型の場（案件を紹介してもらう形）に登録する

クラウドソーシングの小口だけでは、月100万円に届きにくいです。エージェント型の場は、月額の案件を担当者が紹介してくれる形です。ここでは、登録してから最初の面談までの流れを書きます。

## 1. どの場か
登録（アカウントを作る・本人の名前・年収・電話・本人確認）は本人（人）が行う。エージェントは登録の画面を進めない（CW・ランサーズの規約は登録を本人に限る・docs/01。ほかの場も同じ扱いにする）。エージェントがやるのは、登録の前の確かめ（下の 2）と、登録の後の返信の下書き・書類づくり。
- ITプロパートナーズ：週2〜3日・リモートの案件が多い
- Findy Freelance：エンジニア向け。Google アカウントで登録する
- Offers：副業・業務委託向け。登録の途中で「現在の年収」が必須（本人の事実なので人が入れる・推して書かない。経歴や年収が無い・言いたくない人は、この場を飛ばしてよい）

## 2. 登録の前に
- 同じメールで既にアカウントがないかを先に確かめる（受信箱をその場の名前で引く・パスワード再設定に通す）
- 規約で次の3つを読む：アカウントを人に使わせない／場を通さない直接の契約の禁止／秘密保持
- 人間確認のパズル・SMS・本人確認の書類が出たら、機械では押さずに人に頼む
- 人に頼むときは、エージェントが操っているブラウザの窓を前に出して押してもらうのではなく、本人のスマホで登録頁の URL を開いてもらう（2026-11-06 Fiverr の実測：機械で操るブラウザでは人間確認の「長押し」の部品が読み込まれず、出し直しても同じだった）

## 3. 登録の直後に来るメールにすぐ返す
登録すると、多くの場で「希望条件を返信してください」というメールが届きます（例：ITプロは十数項目と面談の候補日）。
- 返信が遅いと、紹介の順番が後ろに回る。届いたら、その日のうちに返す
- 見張り（返事を拾う道具）の送り主の一覧に、その場の送り主を足しておく。足さないと、この便を拾えない
  - 一覧の置き場：`config/profile.json` の「メールの見張り」→「送り元」（メールのドメインの並び。例 `"送り元": ["crowdworks.jp", "lancers.co.jp", "lancers.jp", "<その場の送り主のドメイン>"]`）。送り主のドメインは、届いた1通目の差出人で確かめる
  - tools/henji-mihari.py は Google Workspace の受信箱をサービスアカウントで代理で読む形だけ。無料の Gmail（個人の Google アカウント）はこの形で読めないので、道具は使えない（未設定のまま rc=4 で「見ていない」と出る）。その場合は、巡回のたびに登録に使ったメールの受信箱を手で開く（docs/03）
- 面談の候補日は、面談に出る人の予定の空きから、平日の昼に4つ出す
- 希望の額は「月◯万円以上（税抜）」の形で書く
- 返信は外への送信なので、下書き（希望の項目・額・候補日）をオーナーに見せ、OK の後に送る。このキットにメールを送る道具は無い（henji-mihari.py は読むだけ）。送るのは、登録に使ったメールの受信箱からの返信（オーナーが送るか、オーナーが許した送り方で）

## 4. 職務経歴書
ほぼ必須です。在籍期間・会社を作った年月などの日付が要るので、早めに人に聞いておく。
- 氏名・肩書き・日付は、推測で書かない（設定から差し込むか、本人に聞く）
- 経歴が無い場合：職歴の欄は作らず、templates/keireki.md の形（請け負える仕事・見本の URL・働き方）で作る（docs/06 の「職務経歴書」）。紹介される案件は経歴で大きく変わる（下の「再現するか」）ので、経歴が無いならこの章より、作例を添えて出せるクラウドソーシングの応募（docs/05）を先にする
- 置き場は docs/06 の「職務経歴書」と同じ1本を使い回す
- 出し方は2通り：場のマイページに上げる／担当からの「職務経歴書のご提出のお願い」のメールに返信して PDF を添付する（2026-11-06 ITプロの実測：登録の電話の30分後にそのメールが来て、返信の添付で出せた）。どちらも外へ出すので、PDF と返信の文をオーナーに見せ、OK の後に出す。このキットにメールを送る道具は無いので、返信は 3 と同じ送り方で
- 返信の中で、稼働の条件が変わっていれば伝え直す（前に出した希望の返信は、担当の手元にそのまま残る）

## 5. 稼働の日数
エージェントが作業する形なら、登録の希望の欄は週の日数で絞らずに「週5日のフル稼働」で出す。紹介される案件の母数が増え、月額の高い案件（フル稼働が前提の物）にも当たる見込み（まだ測っていない）。オーナーが出るのは面談だけなので、稼働の日数はオーナーの時間を縛らない
- ただし案件ごとには docs/04 の順番0と docs/01 の線9をそのまま当てる：決まった時間に張り付く・毎週の定例に人が出る・常駐に近い物は、紹介されても受けない。「週5日」は登録の欄の書き方で、時間を約束する返事はしない。会議の有無は 6 のとおり契約の前に聞く

## 6. エントリーと契約の前に聞くこと
- 場によっては、案件への「エントリー」の釦を押すとすぐ送られ、メッセージの欄が出ない（2026-11-06 ITプロの実測：「募集状況を聞く」を押すと「ご紹介可能でしたらエージェントよりご連絡いたします」と出て終わる）
- だから契約の前に聞きたい点（会議の有無・必須の技術の深さ・額）は、エントリーでは届かない。案件ごとに「未確認」として控え（docs/06 の「契約は「できる」と確信した物だけ」の①②③の3行・部屋の番号が無いので `<置き場>/keiyaku/<場>-<案件の番号>.md`）に書き、担当から最初の連絡が来たときに聞く。答えが揃うまで、契約を受ける返事は送らない
- 見送りの理由に出る技術の語を、見送りの記録から数える（語の形で数える：「Go」で引くと Google まで当たる）。開発の側でいちばん多い語の作例を1つ作って公開すると、まとめて出せる案件が増える（2026-11-06 の実測：月額の場の見送りで Next.js・React が4件ずつ・作例を作った後に、見送っていた3件をエントリーの対象に戻せた）
- 必須の技術が経歴に無い案件は、作例（公開した見本の URL）を作ってから「作例で足りるか」を聞く。実務の年数（3年以上など）が必須と書いてある案件は、作例では足りないので出さない
- 新着の見張りは「候補を一覧に書く」だけで終わらせない。判断（出す・見送り）の記録に番号が無い候補が1件でも残っていたら、見張りを止めて中身を出し、あなた（エージェント）を起こす形にする（2026-11-07 の実測：書くだけの見張りで、月額の場の候補9件が約4時間読まれずに残り、そのうち1件は月〜90万円・フルリモートで出せる案件だった）。確かめ方：判断を付ける前に未判断の件数が出て、付けた後に0件になること
- 月額の場の案件は、題名の職種名（PM・ディレクター・マーケ）だけで決めず本文を読む。ただし本文が「人を束ねる」「顧客と対面で折衝する」「社内の承認手続きを回す」中心なら、AI だけでは回せないので見送る（2026-11-07：候補9件のうち8件がこの理由か分野の外）

## 再現するか（経歴なしでも）
- 1〜3（登録・規約・すぐ返す）は、経歴に関係なく同じ手順で再現する（登録は本人・返信は OK の後）
- 紹介される案件の数と額は、経歴と実務の年数で大きく変わる（経歴がある場合だけ、月60万円以上の案件が多く当たる見込み・まだ測っていない）
